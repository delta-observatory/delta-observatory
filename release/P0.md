# P0 distribution feasibility

## Result and boundary

The Linux desktop prototype packages the existing TESS application with its own services and workspace.
Its source is in [release/](README.md), within the public root repository.
The package requires no private repository, Docker, k3s, system PostgreSQL, system Python, or system Node.js.
It includes the current frontend and a native file import menu.
Managed agents, archive acquisition, and a consumer installer remain separate work.

The engineering check uses an isolated Ubuntu 24.04 filesystem with network access disabled.
It exercises a synthetic FITS input through indexing, BLS analysis, export, shutdown, restart, and desktop rendering.
It excludes host home directories, private repositories, and system language runtimes.
The isolation uses the host kernel, not a separate virtual machine.
Fresh desktop installation and distribution security policies still need qualification.

P0 establishes packaging feasibility for one Linux baseline.
It does not complete the full clean-machine acceptance criterion or scientific validation.
The [engineering evidence](evidence/p0-check.json) and [desktop screenshot](evidence/desktop.png) record the check scope.

## Linux requirements

| Requirement | Prototype requirement or measurement |
|---|---|
| Architecture | Linux x86-64. Other architectures remain untested. |
| C library | glibc 2.39 or later. PostgreSQL builds on Ubuntu 24.04. |
| Desktop | X11, or a desktop with compatible XWayland support. The native reference machine uses Hyprland. |
| Desktop libraries | GTK 3, GLib, NSS, NSPR, ALSA, GBM, ATK, AT-SPI, CUPS, D-Bus, Cairo, Pango, X11, XCB, and xkbcommon. |
| Sandbox | Working user namespaces for Chromium. The prototype keeps the renderer sandbox enabled. |
| User | An ordinary user with a writable local workspace. The supervisor refuses root execution. |
| Application files | Approximately 909 MiB of file content before archive compression. |
| Workspace | The engineering fixture, database, results, and caches occupy approximately 66 MiB. Imported observations require additional space. |
| Storage reserve | Startup and import require at least 512 MiB of free workspace space. Import also checks the selected file sizes. |
| Memory | The checked BLS worker uses approximately 258 MiB peak resident memory. This excludes Electron, PostgreSQL, and the API. |
| First service startup | Approximately 2.1 seconds in the isolated check. Desktop startup and package extraction add time. |
| Synthetic BLS job | Approximately 7.7 seconds for 16,000 synthetic 120-second samples. This is not a representative campaign benchmark. |
| Network | Required during the build. The checked local analysis and desktop display work offline. |

The Ubuntu desktop library packages include `libgtk-3-0t64`, `libnss3`, `libasound2t64`, `libgbm1`, and `libatk-bridge2.0-0t64`.
Their dependencies provide the remaining shared libraries.
A normal desktop installation supplies most of these libraries.
The package does not include a Linux kernel, display server, or complete operating system.
Minimum total RAM and large-campaign disk requirements remain unmeasured.

[Ubuntu AppArmor rules](https://documentation.ubuntu.com/security/security-features/privilege-restriction/apparmor/) can restrict user namespaces independently of the installed libraries.
A supported installer must provide a reviewed sandbox configuration for that distribution.
The prototype does not disable the Chromium sandbox or change host security settings.

The build exports only four public Git commits.
The public catalog contains new prototype documentation, not a copy of private research.

## Process and storage boundaries

The supervisor owns PostgreSQL, the API process, and one worker process.
The API and worker communicate through PostgreSQL and existing file references.
The desktop shell calls the API for import indexing.
It does not add API-to-worker calls or new scientific record shapes.
Canonical schemas remain in the database repository.

The workspace marker identifies prototype data.
An exclusive file lock prevents two supervisors from owning the same workspace.
The supervisor clears inherited database settings, component paths, Python paths, and provider credentials.
Each workspace has its own owner credential and a reader with only the `read` permission.
The desktop renderer has no Node.js access.
The desktop blocks external navigation, new windows, external network requests, and browser permission requests.

The public catalog and application code remain in the read-only package during the isolated check.
Imported files enter `raw/tess-spoc-light-curves/` inside the separate workspace.
Import checks filenames, file types, free space, existing content, and copied-file hashes.
The index sees each copied file only after its complete atomic insertion.
Imports retain original files and refuse conflicting destination content.

Shutdown stops the worker and API before PostgreSQL.
Restart retains observation identities, completed results, and identical evidence exports.
Database migration uses the canonical migration script and recorded checksums.
The prototype refuses an unknown newer migration or a PostgreSQL major-version mismatch.
Backup restoration, interrupted migrations, forced-power-loss recovery, and major-version upgrades remain unqualified.

## Engineering evidence and reproduction

The isolated filesystem comes from Canonical's Ubuntu Noble OCI image.
[runtime-sources.json](runtime-sources.json) records its URL and the checked SHA-256.
The `current` download can change, so a changed archive fails the recorded checksum check.
The filesystem includes the desktop libraries and Xvfb, an isolated X display server.
Compiler tools support the runtime build but remain hidden during the execution check.

The local builder uses Bubblewrap with a writable Ubuntu filesystem and a mounted `release/` directory.
It installs build dependencies inside that filesystem, not on the host.
The build packages include `build-essential`, `bison`, `flex`, `pkg-config`, `bzip2`, and `ca-certificates`.
The check also requires `xvfb` and its X keyboard dependencies.
The local user-namespace setup prevents some package configuration steps from completing.
The required libraries execute successfully, but this does not establish a fully configured Ubuntu installation.

The execution check mounts the package read-only and creates a new writable workspace.
It hides the host home, build mounts, and private repositories.
It replaces the system command directory with a small set of operating-system tools.
Python, Node.js, PostgreSQL, Docker, and kubectl are absent from that directory.
Bubblewrap disables network access while preserving local loopback communication.
The Electron check retains its renderer sandbox and uses an isolated visible window for screenshot capture.

The runtime check verifies eleven conditions:

1. A new workspace starts with an empty observation database.
2. Direct API reads require authentication, and the GUI reader cannot write.
3. The public catalog works without private reports.
4. The public method contracts load.
5. A second supervisor cannot own the workspace.
6. The worker indexes the synthetic FITS file.
7. The existing BLS method completes.
8. Every export file matches its hash, and repeated exports are identical.
9. Missing cohort information blocks agent observation reads.
10. Shutdown stops PostgreSQL and removes the runtime record.
11. Restart preserves observations, results, and exports without duplicate observations.

Desktop checks cover loaded fonts, rendered plot pixels, the enabled sandbox, and an empty renderer error list.
The retained screenshot displays the synthetic observation, light curve, folded curve, and periodogram.
Two Node.js checks cover server path restrictions, credential forwarding, and import integrity.
These checks establish engineering behavior only.
They do not establish astronomical recovery rates or numerical accuracy on independent observations.

## Remaining P0 and release qualification

- Test installation on a fresh Ubuntu desktop or virtual machine with its normal kernel security policy.
- Measure complete desktop memory use and startup on representative hardware.
- Check native file selection on the supported desktop environments.
- Define public catalog and cohort ownership before agent integration.
- Replace private catalog source links with package-appropriate public links.
- Complete dependency license, source-offer, vulnerability, and reproducible-build review before public binary distribution.
- Qualify an installer, updates, backup restoration, failed migrations, and interrupted imports before beta release.

The local package and archive remain development artifacts.
No public binary release or external deployment follows from this feasibility check.
